# Project scope

## Current shared UI (overrides older UI/storage notes below)

- Desktop refinement pass: keep the same three-column footer and nine example links on every page. Page-section links are in-page anchors, labelled On this page / In this article; use spacing rather than text pipe separators. Extra article-rail cards and decorative form artwork are desktop-only, not extra mobile reading content.
- Reusable outline icons live in assets/icons.svg. Use a decorative aria-hidden/focusable=false SVG with the .icon class and a symbol reference; currentColor and rem sizing come from CSS. Replace symbols without changing their IDs/viewBoxes; no icon font, third-party library or extra JS.
- A third overview row uses opt-in .card-icon-feature: dominant 9rem icons above centred headings/copy, with four real toolkit topics and working example destinations. Keep descriptions of multilingual samples distinct from unimplemented translation routing.
- Mobile overview (up to 50em) displays two of each four-card treatment: Service/Detail, Pricing/Gallery, Proportional scale/Native interactions. Other six cards use .overview-desktop-card and remain available on desktop; destinations remain in navigation/footer. .overview-media-grid uses two mobile columns for Profiles/Products, followed by full-width Editorial media. Do not change desktop grids or approved utility-strip sizing for this composition.
- .overview-examples-grid pairs Service/Detail and Pricing/Gallery in two mobile columns; .card-icon-feature cards each span the full width. Typography, icon sizes and utility controls remain unchanged.
- Established lab examples are distributed: article.html#wrapping and #languages; catalog.html#containers and #states; contacts.html#field-states; gallery.html#missing-media; service.html#rhythm. Their opt-in CSS is assets/examples.css, imported by theme.css. experiments.html is intentionally a minimal no-active-experiments page with links to these destinations; do not restore duplicated demonstrations or the retired experiments.css file. Keep ordinary/pretty/balanced comparisons explicit and static form states separate from actual validation.
- Overview demonstrates two card treatments: first four cards use .icon-heading.icon-heading-reserved with original-size icons and a two-line reserve; last four use .card-icon-flow with compact description icons, first-line-only wrapping and justified text (last line start-aligned). Keep these opt-in theme classes, not global paragraph styling. Cookie settings and its live status belong inside the footer's right-hand column below the developer note, not in a separate footer row. The developer note calls viewport/load-time diagnostics optional prototyping aids.
- FAQ groups use native details name attributes (a different name per group); all start closed and only one stays open where supported. Do not group mobile navigation or independent media disclosures with FAQs. No accordion JS fallback.
- Desktop article rail includes a disabled feedback form with email and optional Messenger phone fields in one row. Phone input is type=tel, autocomplete=tel, LTR; message uses auto direction. Backend/actual sending remain out of scope; mobile composition is deferred.
- Article feedback is the final rail item. The article body and rail share the first grid row; .article-related occupies the next row in the left column. Desktop rail uses natural-height flex children and space-between so the form's bottom aligns with the end of sufficiently long body text, without JS measurements or fixed offsets. A shorter body cannot determine the bottom if the rail itself is taller; preserve natural non-overlapping flow.
- Prefer en dashes (–) to em dashes (—) in public copy as pages are edited. Do not run a separate whole-site replacement pass just for punctuation.

- Theme and cookie UI are now shared across nine pages. Both manual theme and versioned cookie preferences use localStorage with no automatic expiry; unavailable storage must not break the UI. No trackers, consent enforcement or production consent manager are connected.
- All nine pages use static .css-top HTML wrappers and assets/css-header.css (imported by theme.css) for sticky positioning and scroll-driven compaction. Header creation, scroll listeners and header measurements have been removed from interactions.js. Unsupported scroll timelines and reduced-motion use a sticky expanded header.
- The CSS Grid header row reserves this English navigation's expanded dimensions. Recheck it for changed labels, fonts, multi-row navigation or new header controls; it is not a general intrinsic-height solution. The animation follows 0–8rem of scroll rather than a 180ms timer. Demo notes stay outside the sticky group.
- Service-strip controls do not scale on hover. Existing mobile control sizes and all three scale regimes remain unchanged. Theme/consent widgets and footer reopening controls are static HTML on all nine pages; interactions.js only wires behaviour, storage and consent-height reservation, never creates widgets.
- assets/theme-init.js is an approved tiny synchronous head script, before styles/content, that restores only valid saved light/dark choices. No async/defer: prevent a system-to-manual palette flash. Storage failures fall back to the system palette. The extra local request is cacheable; no third-party resources. After initial cookie choice, focus moves to visible main content without scrolling; after reopening settings from the footer, it returns to that opening button. Temporary tabindex=-1 on reading blocks is removed on blur and does not add a Tab stop.

- Prastora is an independent experimental CSS toolkit. Do not modify legal-status, framework or HTML archives when working here.
- Public-facing copy is English and describes the toolkit, its approach and page patterns, not a fictional company. Keep claims proportional to implemented features.
- experiments.html is the testing ground for future comparisons; established demonstrations now live in the relevant page examples. User approved balance for all headings and pretty for short block copy; ordinary-wrapping comparisons override these explicitly. Keep the existing three proportional scale regimes; the user deliberately prefers them over smoothing.
- core.css contains reusable layout primitives; theme.css contains demonstration branding and composition.
- Keep full-width proportional rem scaling (128 units desktop, 64 mobile, 160 wide screens). Typography follows the tested mobile sizes from legal-status. No default max-width container or upper scale cap. --scale-min is an optional configurable floor, not enabled by default.
- index, service, article, catalog, product, pricing, gallery and contacts are static examples, not a CMS or shop. Pricing amounts are illustrative, not Prastora offers; selection buttons and contact submission stay disabled. Gallery uses original local assets/gallery.svg artwork and links to actual example pages. Contacts links to the real public repository, not invented addresses or map integrations. No third-party fonts, trackers or embeds. Client JavaScript is limited to the explicit exceptions below. Forms are disabled until a real backend is configured. Do not imply placeholder links, media or prices are real.
- Shared headers are duplicated deliberately for this static pass; keep the same eight-page navigation across all nine pages including the lab. Consider build-time templates later, not browser injection.
- User-approved temporary exception: assets/viewport.js and viewport.css display viewport dimensions and Navigation Timing load-event duration on all nine pages for device review, separated by | with no visible Viewport label. Timing is not a page-performance score; it depends on caching and the browser's navigation entry. Keep diagnostics separate from core; the site works without this script. Remove their HTML hooks and checker exception when retiring diagnostics.
- User-approved UI exception: assets/interactions.js enhances all nine pages with a fixed, scroll-compacting two-row header. Compaction uses a brief CSS transition, disabled for reduced motion; preserve the expanded header reserve throughout both directions of the transition. On the lab only, it toggles the system-default theme through one sun/moon button and operates a consent UI example. The user requested slim single-row utility strips and We use cookies / Accept all / Necessary only / Settings without visible demo explanations. Mobile strip sizes are approved: do not reduce them further. Additional compact sizing is restricted to widths above 50em, including wide-screen mode. No storage or trackers: choices last for the current page load, not a production consent manager. Record implementation limitations in CHECKS.md rather than cluttering the strip. No-JS pages retain normal headers and content. Supporting area is a duplicate lab card hidden on mobile, not a rule to hide all sidebar content.
- Do not use px for CSS dimensions. Component sizes use rem; media queries use em (50em / 125em) to keep thresholds independent of the viewport-linked root scale. The utility strip includes an English-only language control and disabled sign-in example, not real translation or authentication.
- Use logical CSS properties and test whole-page RTL and mixed Arabic/Chinese content. Translation routing is not implemented; future translations must preserve page identity.
- .aligned is opt-in for cards with one heading and --items list rows. It is not suitable for arbitrary card markup; ordinary lists use .prose.
- Test 320, 360, 390, 423, 609, 800, 801, 1280, 1463, 1999, 2000 and 2560 CSS pixels. Check menu, disclosures, wrapping, SVG placeholders, keyboard focus and overflow. Do not treat geometry checks as physical phone testing.
- Never publish a new remote repository without confirming its destination and visibility with the user.
