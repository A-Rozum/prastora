# Project scope

- Prastora is an independent experimental CSS toolkit. Do not modify legal-status, framework or HTML archives when working here.
- Public-facing copy is English and describes the toolkit, its approach and page patterns, not a fictional company. Keep claims proportional to implemented features.
- experiments.html and assets/experiments.css are the testing ground for container queries, system/manual colour schemes, static UI states, a consent-bar UI demo and alternative compositions. User approved balance for all headings and pretty for short block copy; ordinary-wrapping lab comparisons override these explicitly. Keep the existing three proportional scale regimes; the user deliberately prefers them over smoothing.
- core.css contains reusable layout primitives; theme.css contains demonstration branding and composition.
- Keep full-width proportional rem scaling (128 units desktop, 64 mobile, 160 wide screens). Typography follows the tested mobile sizes from legal-status. No default max-width container or upper scale cap. --scale-min is an optional configurable floor, not enabled by default.
- index, service, article, catalog, product, pricing, gallery and contacts are static examples, not a CMS or shop. Pricing amounts are illustrative, not Prastora offers; selection buttons and contact submission stay disabled. Gallery uses original local assets/gallery.svg artwork and links to actual example pages. Contacts links to the real public repository, not invented addresses or map integrations. No third-party fonts, trackers or embeds. Client JavaScript is limited to the explicit exceptions below. Forms are disabled until a real backend is configured. Do not imply placeholder links, media or prices are real.
- Shared headers are duplicated deliberately for this static pass; keep the same eight-page navigation across all nine pages including the lab. Consider build-time templates later, not browser injection.
- User-approved temporary exception: assets/viewport.js and viewport.css display viewport dimensions and Navigation Timing load-event duration on all nine pages for device review, separated by | with no visible Viewport label. Timing is not a page-performance score; it depends on caching and the browser's navigation entry. Keep diagnostics separate from core; the site works without this script. Remove their HTML hooks and checker exception when retiring diagnostics.
- User-approved UI exception: assets/interactions.js enhances all nine pages with a fixed, scroll-compacting two-row header. Compaction uses a brief CSS transition, disabled for reduced motion; preserve the expanded header reserve throughout both directions of the transition. On the lab only, it toggles the system-default theme through one sun/moon button and operates a consent UI example. The user requested slim single-row utility strips and We use cookies / Accept all / Necessary only / Settings without visible demo explanations. Mobile strip sizes are approved: do not reduce them further. Additional compact sizing is restricted to widths above 50em, including wide-screen mode. No storage or trackers: choices last for the current page load, not a production consent manager. Record implementation limitations in CHECKS.md rather than cluttering the strip. No-JS pages retain normal headers and content. Supporting area is a duplicate lab card hidden on mobile, not a rule to hide all sidebar content.
- Do not use px for CSS dimensions. Component sizes use rem; media queries use em (50em / 125em) to keep thresholds independent of the viewport-linked root scale. The utility strip includes an English-only language control and disabled sign-in example, not real translation or authentication.
- Use logical CSS properties and test whole-page RTL and mixed Arabic/Chinese content. Translation routing is not implemented; future translations must preserve page identity.
- .aligned is opt-in for cards with one heading and --items list rows. It is not suitable for arbitrary card markup; ordinary lists use .prose.
- Test 320, 360, 390, 423, 609, 800, 801, 1280, 1463, 1999, 2000 and 2560 CSS pixels. Check menu, disclosures, wrapping, SVG placeholders, keyboard focus and overflow. Do not treat geometry checks as physical phone testing.
- Never publish a new remote repository without confirming its destination and visibility with the user.
