# Built with Prastora – how we see the section

Not yet built. A record of the idea, to start from when there are real sites to show.

## What it is
Not a gallery of links and not a template showcase. A set of short case pages ("files"), one per real
site made with Prastora. Authors differ; the framework is what joins them – like a studio portfolio,
with the tool in place of the studio.

## One case page
1. Snapshot at launch in three windows – phone, ordinary desktop, 4K – taken with our own tool, so all
   cases look alike and nobody picks flattering angles. Date of the snapshot.
2. Link to the site as it is now; optionally a Wayback Machine copy of the launch version.
3. Before/after for redesigns: the old site and the new one in the same three windows.
4. Facts: kind of site, author, launch date, Prastora version (or the commit the styles came from),
   number of pages, themes and components used, what had to be written specially.
5. Speed: Google PageSpeed Insights scores at launch, mobile and desktop. No leaderboard while there
   are few sites.
6. The author's story: three to five decisions, why, what was hard.
7. What went back into the framework: components added or bugs fixed because of this site, linked to
   the commits.

## Section page
Grid of cases with launch snapshots, filters by kind of site and Prastora version, newest first.

## Mechanics, later
A case is a small data file plus snapshots made by the tool; pages are built from one template.
Submissions through GitHub; simple acceptance rules (live, made with Prastora, author agrees); the
author can ask for removal. Build the mechanism when there is a second site.

## Working rule for client sites
A client site keeps its own copy of Prastora's styles from a known version and updates on purpose.
Anything the site needs that Prastora lacks is made in Prastora first (experiments.html or a
component), then copied – so the case can point to the change.
